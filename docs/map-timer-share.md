# タイマー・活動地図・共有機能

## 保存方針

- 完成した活動記録は従来どおりIndexedDBへ保存する。
- 計測中のタイマーは完成記録と分離し、端末のlocalStorageへ1件だけ保存する。
- タイマーは端末間同期しない。複数端末からの二重終了・重複保存を避けるため。
- 活動中に数えた配布枚数はタイマーへ一緒に保存し、終了時に入力欄へ引き継ぐ。押し間違いを1回分戻せるよう加算の履歴も持つ。
- 初回起動時にサンプルデータを入れるかを選ばせる。入れたサンプルには印を付け、設定画面からまとめて削除できるようにする。自動では投入しない。
- 分析の表示設定・並び順・配布目標は端末のlocalStorageへ保存し、端末間同期しない。配布目標はアカウントごとに持つ。
- 活動予定も端末のlocalStorageへアカウントごとに保存し、端末間同期しない。通知は端末ごとの機能のため。
- 設定のバックアップは、全アカウントの活動記録・追加スポット・端末設定・配布目標・活動予定を1つのJSONにまとめる。復元はまとめて入れ替える方式にし、部分復元はしない。
- バックアップの復元はこの端末のデータだけを入れ替える。同期にログイン中はクラウドの内容で上書きされることがあるため、画面でログアウトを案内する。
- 標準スポットはアプリに同梱し、利用者が追加・変更したスポットをFirebaseの `users/{uid}/spots/{spotId}` で同期する。
- 追加・変更したスポットはアプリ内の全アカウントで共通利用する。
- 設定の「地図でピンを追加・編集」から、標準ピンを含む既存スポットの位置・地区・地名・名称を変更できる。
- 2026年8月13日時点で地図上から確認・調整した全60地点を標準ピンとして同梱する。
- 標準ピンの変更は上書きとして保存し、「標準の名称・位置に戻す」で確認済みの標準位置へ戻せる。
- ピンは「非表示」で後から再表示できるほか、「削除」でマスタから取り除ける。ピンを削除しても過去の活動記録は削除しない。
- スポットIDは編集前後で維持するため、IDに紐づく過去の活動量マップも新しいピン位置へ追従する。過去の活動記録本文に保存済みの名称は変更しない。
- GPSで取得した現在地は保存しない。利用者が確定したスポットの座標だけを保存する。

## OpenStreetMap

- 表示はLeaflet 1.9.4とOpenStreetMap標準タイルを利用する。
- 地図上にOpenStreetMapのクレジットを常時表示する。
- Service Workerで地図タイルを独自キャッシュ・一括取得しない。
- `scripts/geocode-spots.mjs` はNominatimを1.1秒以上の間隔で呼び出し、候補を `data/spot-geocode-review.json` に出力する。
- 候補確認後、`scripts/build-spot-coordinates.mjs` で公開用の `data/spot-coordinates.js` を生成する。
- 標準60地点のうち、施設名で取得できなかった地点は同一駅・街区の近似座標を初期表示に使用する。正確な活動位置は地図から新しいスポットとして追加できる。

## 予定のリマインド

- 予定は日付・時刻・場所・メモを持ち、1時間前と開始時刻に知らせる。
- ブラウザの通知は、アプリを開いている間だけ出す。閉じている間に鳴らす仕組み（プッシュ通知）は持たない。
- 閉じていても知らせたい場合のために、端末カレンダーへ登録する `.ics` を書き出せるようにする。`.ics` には1時間前のアラームを入れる。
- 通知の許可は利用者が押したときにだけ求める。許可が無い・使えない端末では画面内のメッセージへ切り替える。
- ダウンロードのファイル名は英数字にする。日本語だけの名前は拡張子ごと落とすブラウザがあり、`.ics` がカレンダーで開けなくなるため。

## 共有

- 共有文・画像には氏名、肩書、署名、ロゴを付けない。
- 参加者名、トラブル内容、内部メモ、GPS現在地は自動共有しない。
- Web Share API対応端末では端末標準の共有画面を開く。
- 非対応環境ではテキストをコピーし、PNG画像はダウンロードする。
- 一覧では選択記録だけを集計し、分析では全表示記録から実績画像を生成する。
- 分析の「レポート」は選んだ期間と、その直前の同じ長さの期間を比べてテキストと画像にする。
- 分析の全ダッシュボード（グラフ・表・ヒートマップ・ランキング・活動量マップ）に画像共有ボタンを置く。
- 共有画像は画面のスクリーンショットではなくCanvasへ描き直す。表示中の並び順・絞り込み・指標をそのまま反映する。
- 行や列が多い表は上限を決めて省略し、省略した件数を画像内へ注記する。
- 活動量マップの共有画像は表示中の範囲のタイルを取得し直して描く。取得できない場合は背景なしで出力し、その旨を注記する。
- 地図の共有画像にもOpenStreetMapのクレジットを描画する。

## 公開前確認

1. 375px幅で全5画面と地図モーダルに横はみ出しがない。
2. タイマーが再読込後も復元される。
3. ピン選択で地区・地名・スポット・spotIdが入力される。
4. 新規スポットが設定画面へ表示され、編集・非表示・再表示できる。
5. 標準ピンの変更が同じspotIdで保存され、確認済みの標準位置へ戻せる。
6. 追加ピンと標準ピンを削除でき、削除後も過去の活動記録は残る。
7. 過去の旧名称スポットも活動量マップへ対応付けられる。
8. 一覧の選択共有と分析の画像共有に非公開項目が混ざらない。
9. 分析の全ダッシュボードで画像共有ボタンからプレビュー画像が生成される。
10. 配布目標を入れると目標ペースの線と必要ペースが表示され、再読込後も保持される。
11. 一覧の検索がスポット名・メモ・テーマに一致し、複製から日付が当日の新規入力が開く。
12. バックアップを書き出して復元でき、別形式のファイルは拒否される。
13. 予定を追加すると一覧と当日の通知に反映され、`.ics` を保存できる。
14. 活動中のカウンターが再読込後も残り、終了時に配布枚数へ入る。
15. 初回起動でサンプルの有無を選べ、サンプルだけを後から削除できる。
16. 予定の「この予定で記録」で場所と開始時刻が入った入力画面が開く。
17. Firestoreルールテストで本人以外のspots読み書きが拒否される。
